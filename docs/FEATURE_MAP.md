# Feature map — coverage contract

Phase 1 planned coverage; implementation paths below are destinations for later phases, not claims that the files already exist. The [repository manifest](planning/REPOSITORY_MANIFEST.txt) lists all planned files. During implementation, paths become links and CI rejects missing targets. All task IDs link to the existing [task catalog](GYM_TASK_CATALOG.md).

Each row is a feature group taught together in one focused example and exercised in the module's Claims Copilot use case. Every semicolon-separated feature receives all six listed graded tasks. Task acceptance must exercise the feature, not merely mention it. Each example has an explanation, an analogy, a generated diagram where supported, a superstep account, a predict/run/reveal exercise, an expected result, and a use/do-not-use discussion. Complex examples may be split into extra numbered files while keeping these stable coverage IDs.

## Cross-cutting acceptance rules

- Versioned output handling: v2 for Python graph invoke/stream; all seven stream modes are covered by 18-A. Beta event streaming is explicit in 18-C and B4-A. Do not confuse event-protocol versions with stream-mode versions.
- Core prerequisites: pytest assertions start in 00-C, Pydantic in 02-A, LLMs and messages in 02-C/08, embeddings in 11-C, and async/await before MCP in 16-A. Module 07 uses a pre-supplied nested graph only to identify namespaces; creating subgraphs is taught in 13. Module 10 uses an adapter first, with full subgraph mechanics in 13.
- Historical API spellings and static debugging breakpoint syntax appear only in the migration guide, to honor the requested banned-API scan. Module 06 explains the distinction; module 20 links to the executable debugging example in that guide.
- Live providers are optional. Every automated exercise uses deterministic fakes or plain Python; no network sockets or API keys are needed. Local MCP integration uses stdio. Postgres, Docker, Studio, and remote endpoints have separately marked integration/live checks.
- Concurrency assertions compare causality and superstep batches; sibling completion order is not a guaranteed sequence.
- Six exercises per feature is the floor. Coverage review may increase the catalog if a group needs more focused tasks.
