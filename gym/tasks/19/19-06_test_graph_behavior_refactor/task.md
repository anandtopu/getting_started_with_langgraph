# 19-06 — Refactor test graph behavior: Require both implementations to match the independent expected route.

Type: refactor. Difficulty: hard. No live model, key, or network is required.

## The claim scenario

A pytest test is a function whose assertions express requirements. Parametrized tests run it over many inputs. Compare pure node rules and whole graphs against independently specified boundary outcomes; comparing two copies of the same implementation can preserve the same bug. Fake models make orchestration tests repeatable, not model accuracy measurable.

## Your task

Require both implementations to match the independent expected route. Preserve run(case) and the existing public functions. Return a JSON-compatible result. Do not import the reference solution or hard-code one fixture.

## Inputs and acceptance

```json
[
  {
    "amounts": [
      100000,
      100001,
      500001,
      true
    ]
  },
  {
    "amounts": [
      0,
      -1,
      500000
    ]
  },
  {
    "amounts": []
  }
]
```

cases.json declares the expected output or expected exception type for every input. Exceptions are observed by the grader; import errors are setup failures. The starter's demo prints a known runtime error when appropriate, so you can inspect it without losing the exercise context.

The suite checks more than the default claim. Keep identities, boundary behavior, and isolation intact. A Design pass includes a separate self-review and is not an automatic architecture-quality judgment.
